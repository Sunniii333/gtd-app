# Sync ผ่าน Firestore แทนการเก็บเฉพาะใน localStorage

เดิมแอปเป็น local-first ข้อมูลอยู่ใน localStorage ของเบราว์เซอร์เดียว ผู้ใช้ (คนเดียว) ต้องการเห็นข้อมูลชุดเดียวกันทั้งบนคอมและมือถือ โดยไม่เสียเงินและยังใช้ได้ตอนไม่มีเน็ต จึงเลือก Firebase Firestore (free tier) เป็น Cloud copy เพราะมี offline persistence ในตัว อัปเดตข้ามเครื่องแบบ realtime และไม่พักโปรเจกต์เมื่อไม่ได้ใช้ ล็อกอินด้วย Google และต้องล็อกอินก่อนใช้งาน (ไม่มีโหมดเครื่องเดียว) การชนกันใช้ Last write wins ทีละ Item/Project โดยนับตามลำดับที่ไปถึง Cloud copy (พฤติกรรมปกติของ Firestore) ไม่เทียบนาฬิกาเครื่อง เพราะผู้ใช้คนเดียวแทบไม่แก้ชิ้นเดียวกันบนสองเครื่องตอน offline แต่ละ Device ส่งขึ้นเฉพาะ record ที่ตัวเองเปลี่ยน ไม่อัปโหลดทั้งก้อน การลบจึงไม่ถูกเครื่องที่มีสำเนาเก่าคืนชีพ และไม่ต้องมี tombstone ทำ PWA ไปพร้อมกันเพื่อให้เปิดแอปได้ตอน offline

## Considered Options

- **Supabase** — ถูกพักเมื่อไม่ได้ใช้ ~7 วันบน free tier และต้องเขียน offline queue เอง
- **ไฟล์ JSON ก้อนเดียวบน Gist/Google Drive** — ไม่ realtime และการแก้สองเครื่องพร้อมกันทับกันทั้งก้อน

## Consequences

- Export ยังคงไว้เป็น backup; Import กลายเป็น "แทนที่ Cloud copy ทั้งหมด" หลังยืนยัน
- Device แรกที่ล็อกอินเจอ Cloud copy ว่าง จะอัปโหลดข้อมูลในเครื่องขึ้นไปเป็นข้อมูลตั้งต้น; Device ถัดไปถูกแทนที่ด้วย Cloud copy
- ผูกกับ Firebase: ถ้าจะย้ายต้องเขียนชั้น sync ใหม่ แต่ Export JSON ยังใช้ย้ายข้อมูลได้
